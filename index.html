About Me

I build and run cloud infrastructure for a platform serving around forty internal projects: provisioning environments, wiring delivery pipelines, controlling who can reach what, and making sure that when something breaks there is a signal rather than a guess.

My preference is boring infrastructure. Reusable modules instead of hand-built snowflakes, permissions that expire instead of accumulate, and pipelines that fail loudly before production does.

Most of what I build is meant to be used by other engineers without asking me first. That is the part I like.

Where I Make A Difference

Infrastructure as code Ongoing

Separate AWS accounts · around 150 environments

  • Around 150 project environments, about forty of them production, described in Terraform, with one state key per project so applies stay isolated and blast radius stays small
  • 21 reusable modules covering networking, compute, data, DNS and identity, built on top of pinned upstream ones
  • Atlantis enforces plan-first with repository locking; production changes need an explicit confirmation

Access and security Ongoing

Identity, least privilege, audit

  • One access request drives GitLab, Jenkins, AWS SSO and the database — with time-boxed roles instead of standing admin
  • Periodic access reviews across VPN, GitLab, AWS and database users, delivered as a report rather than a spreadsheet nobody opens
  • GuardDuty, Inspector and WAFv2 baselines, plus pre-commit gates running secret scanning, IaC linting and policy checks before anything reaches a plan

Delivery pipelines Ongoing

Jenkins, GitLab CI, GitHub Actions

  • Shared library steps instead of per-project copies, so build logic exists once
  • Container builds split into independently cacheable stages — a code-only change no longer rebuilds the world
  • Images scanned in the registry, with findings aggregated per image instead of per scan

Observability Ongoing

Metrics, logs, alert design

  • 135 CloudWatch alarms and 34 log groups, with the thresholds tuned until a page actually meant something
  • Saved Logs Insights queries for the questions that come up repeatedly, so incidents do not start with writing a query
  • Alerts routed somewhere actionable, carrying enough context to act without opening the console

Cost control Ongoing

Attribution and rightsizing

  • Enforced a tagging standard so spend could be attributed per project and environment, which is what made any optimisation possible at all
  • Identified idle and oversized resources and rightsized the obvious ones
  • Cost review became a routine instead of a firefight

Some Things I've Built

  • Featured Project

    Behaviour-based WAF scanner

    Signature-based WAF rules see a request, not an application. They cannot know which routes a service actually exposes, or what normal traffic looks like for it.

    This scanner has been running in production since April 2026. It reads load balancer logs across the fleet, builds a per-IP feature vector, and scores it with an Isolation Forest trained on each project's own baseline, blended with route-aware rules. Every decision carries its reasons, and blocked addresses go straight back into WAF IP sets, so the next run sees the effect of its own decisions.

    • Python
    • scikit-learn
    • AWS WAFv2
    • S3

  • Featured Project

    Self-service environment platform

    Standing up a new project used to be days of manual work spread across five systems, and tearing one down was worse. One job now creates the GitLab project with a protected branch, the Jenkins folder and its jobs, the AWS infrastructure through Terraform, the database and the application config, then builds the image and starts the service. Six teardown variants mirror it, with dev and production separated and ordering guarantees so nothing is left orphaned.

    • Jenkins
    • Ansible
    • Terraform
    • GitLab
    • AWS

  • Featured Project

    Multi-account AWS platform

    Infrastructure was hand-built per project, assembled by copy-paste and tribal knowledge, and every environment was a slightly different snowflake. Rebuilt as 21 reusable Terraform modules spanning separate AWS accounts, with one state key per project and environment so an apply in one place cannot reach into another. Drift became detectable instead of discovered during incidents.
